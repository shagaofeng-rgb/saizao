# 赛兆后台运营说明

## 栏目与真实数据来源

| 栏目 | 主要任务 | 数据来源 |
| --- | --- | --- |
| 业务概览 | 核对询盘、访客、零售与 Google 指标 | Supabase 业务表、Google Search Console、GA4 实时接口 |
| 访客中心 | 按时间、国家和来源追踪已记录的访问 | `analytics_visitors`、访问事件与会话 |
| 询盘管理 | 查询、分配、标记、跟进和导出客户询盘 | `leads`、`lead_notes` |
| 产品内容 | 编辑真实商品资料、图片、规格、库存与发布状态 | `products`、`retail_variants` |
| 分类管理 | 维护产品和资讯分类、排序、启停与归档 | `content_categories` |
| 媒体资料 | 上传文件、维护说明、查找引用和归档 | Supabase Storage、`media_assets` |
| 零售订单 | 查看订单与执行既有履约流程 | `retail_orders` 及关联表 |
| 配送区域 | 维护既有零售配送配置 | `retail_shipping_zones` |
| 资讯内容 | 编写、修改、审核与发布资讯 | `articles` |
| 搜索展示 | 核对已发布内容的搜索标题、摘要与封面 | `products`、`articles`；不推断搜索引擎收录 |
| 数据核验 | 手动检查 Google 接口，并保存每次核验状态 | Google API、`integration_sync_runs` |
| 团队账号 | 管理原有账号与角色 | `private.admin_accounts` |
| 操作记录 | 核对关键后台操作 | `admin_audit_logs` |

产品和资讯的修改前版本保存在 `content_revisions`。目前界面展示最近修改时间，恢复版本仍须由管理员核对后执行，避免覆盖新资料。

## 权限与发布规则

- 所有栏目要求已登录。管理员与超级管理员可以管理团队、配送区域、核验记录和操作记录。
- 内容编辑员可以编辑草稿和待审核内容；发布、下架及修改已发布内容仅限管理员。销售可以处理询盘和查看订单；客户资料导出及邮件重发仅限管理员。
- 发布商品前必须有已启用分类、主图、简介和正文。开启零售时，还需至少一个有正数售价的上架规格。设计示例不能发布。
- 发布资讯前必须有已启用分类、封面和正文。已归档媒体不能再从媒体库选择；正在被产品或资讯引用的文件不得归档。
- 所有数字都从实际记录读取。无记录时显示空状态，Google 未配置或未授权时显示相应状态，不填充演示数字。

## 上线与回退

1. 在部署代码前先执行 `supabase/migrations/20261015132411_admin_operations_completion.sql`。迁移只新增字段、表、索引和函数，不删除既有业务资料。
2. 执行 `pnpm lint`、`pnpm exec tsc --noEmit` 和 `pnpm build`，再部署代码。
3. 上线后检查分类、媒体、询盘详情、产品/资讯编辑、搜索展示和 Google 数据核验页面。仅用既有真实记录核验，不创建虚构业务数据。
4. 若新版代码出现问题，先回退 Vercel 部署到上一个稳定版本。新增数据库结构保持不动即可兼容旧版代码；不要直接删除新表或字段，以免丢失上线后产生的数据。
5. 恢复数据前先核实 Supabase 项目的可用备份策略与恢复点。当前仓库的迁移文件不是业务数据备份，操作记录也不能代替备份。

Google 数据核验是管理员手动触发，不是定时任务。第三方接口暂时不可用时，历史快照只反映当次运行，不当作当前数据。
