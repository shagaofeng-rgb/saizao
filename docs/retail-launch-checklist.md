# 赛兆零售上线清单

当前代码已包含商品详情模板、后台商品编辑、规格与库存、购物车、配送报价、PayPal 订单创建/回跳捕获/签名验证、订单管理。线上支付默认关闭；这不是故障，而是避免在收款主体和真实商品信息未确认前收取款项。

## 必须先确认的业务资料

1. 收款主体注册国家/地区及其 PayPal Business 账户；确认该账户具备跨境收款能力。
2. 首批真实商品的名称、描述、实物图片、规格、SKU、USD 售价、可售库存、重量、合规资料。不要把设计示例当作真实商品发布。
3. 首批配送国家、运费、满额免运费门槛、预计送达时间，以及各地适用税费处理方式。税费须按实际法律/财务意见配置。
4. 退换货、隐私、订单客服和配送条款。正式收款前应有对顾客可见的政策页面。

## 平台配置

- Vercel Production 中添加 `PAYPAL_ENV=live`、`PAYPAL_CLIENT_ID`、`PAYPAL_CLIENT_SECRET`、`PAYPAL_WEBHOOK_ID`。密钥只放服务端变量，绝不使用 `NEXT_PUBLIC_`。
- PayPal Webhook URL：`https://www.szxj6899.com/api/shop/paypal/webhook`，至少订阅 `PAYMENT.CAPTURE.COMPLETED`。将这个 Webhook 的 ID 填入 `PAYPAL_WEBHOOK_ID`。
- 在后台“配送区域”配置并审核真实可配送国家，保持其他区域关闭。
- 在后台“产品内容”新建真实产品，进入“编辑详情”上传图片和文案、配置规格/库存。先在预览页检查，再发布。
- 完成沙盒与生产小额联调、核对支付金额/库存/订单/退款流程后，最后才把 `RETAIL_CHECKOUT_ENABLED=true` 设为 Production，并重新部署。

## 当前安全边界

- 设计示例为 `is_demo=true` 的后台草稿，无法通过后台发布；公开商品列表排除它。
- 客户端价格和库存只用于展示；结算时由数据库重新计算并原子预留库存。
- 所有零售表启用 RLS；匿名用户和普通登录用户不能直接读取订单及客户资料。
- PayPal 回跳校验订单 ID、短期 HttpOnly Cookie、金额、币种和捕获状态；Webhook 需经 PayPal 签名验证。
- 没有真实支付密钥和配送区域时，购买操作不可用。不会生成模拟订单或虚假销量。
